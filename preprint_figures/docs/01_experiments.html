The three experiments

Three datasets, three protocols, three response directions. The pipeline treats them uniformly, but they are not interchangeable — understanding the differences explains many figure quirks.

How to study this

  1. Read the protocol summaries — note the response direction.
  2. Compare channel layouts (NRK has 4, C2C12 has 3, PC3 has 1).
  3. Note where stim timing comes from for each.
  4. Open preprint_figures/common/config.py in parallel.

Dataset 1

c2c12_dmso_09APR26 · C2C12 myoblasts

Protocol

Perfusion pulse train

15 min of neutral acclimation → three training blocks of 5 × (2 min DMSO + 8 min neutral) → 30 min rest between blocks.

Stimulus minutes: [15, 25, 35, 45, 55] | [95, 105, 115, 125, 135] | [175, 185, 195, 205, 215] per channel.

Layout

Three-channel imaging

Three channels imaged simultaneously: channel 1, channel 2, channel 3. Each lives in its own subdirectory under EXPERIMENTS/other/c2c12_dmso_pulses_perfusion_09APR26/ with frames/, masks/, analysis/.

Timing

From per-channel CSV

Each channel has a timestamps/*.csv with frame filename + datetime + minutes. Stim minutes are mapped to the nearest-datetime frame.

Response

Increase from baseline

DMSO drives the bioluminescent reporter up. F0 is the per-cell mean of frames [0, first_stim) — i.e. the 15-min acclimation. Response window: frames [stim+1, stim+8).

Dataset 2

pc3_dmso_23MAR26 · PC3 prostate cancer

Protocol

Same 3 × 5 pulse train, shorter acclimation

10 min neutral, then identical block structure to C2C12 with offsets shifted: [10, 20, 30, 40, 50] | [90, 100, 110, 120, 130] | [170, 180, 190, 200, 210]. Total ≈ 220 min.

Layout

Single-channel, flat root

Unlike C2C12 / NRK, the data lives directly at <dir>/{frames,masks,analysis} — no per-channel subdirectory. The pipeline detects this via the single_channel_root flag in config.

Timing

Flat-root timestamps.csv

The CSV lives in the root dir (... 23MAR26 timestamps.csv). If absent, the pipeline falls back to file modification times to infer minutes.

Quirk

Dead frames are common

The PC3 camera occasionally drops frames or produces dark snaps. filter_dead_frames: True is set: a 6 σ MAD test on the bg trace masks outliers, then linear interpolation fills them. Because the dead-frame flag also gates in-cache BG-coef interpolation, PC3's BG cache is keyed separately at bg_cache/pc3_dmso_23MAR26__filterdead.pkl — clearing the cache should target that path, not the unsuffixed name.

Dataset 3

nrk_acid_13APR26 · NRK kidney with hardware feedback

Protocol

Closed-loop acid pulses

The PE_Pipeline V5 hardware monitors mean luminosity in real time. When luminosity drops below a setpoint, it injects a 30 s acidic-media pulse to drive luminosity back up. The setpoint is changed mid-experiment (the real setpoint event).

Layout

Four channels (paired)

Two acquisition runs, each with two channels: channel 1 A, channel 2 B (run A) and channel 1 C, channel 2 D (run B). All under one experiment directory.

Timing

From monitoring.log

monitoring.log from PE_Pipeline records every frame timestamp, every "add acidic media" decision, and every setpoint change. The pipeline parses all three. More on stim resolution →

Response

Decrease from baseline

Acid drives luminosity down. Response window: frames [stim+1, stim+8), min within window − baseline. F0 is still the pre-first-stim mean.

Window

Only first 30 minutes

time_window_minutes: 30.0 is set, so all corrected_lum, bg_trace, and stim_frames are clipped past 30 min. Long experiments are shortened to the dynamics-of-interest window.

Dedup

Pulses within 10 frames are merged

The controller can fire several acid pulses in rapid succession. PULSE_DEDUP_FRAMES = 10 drops near-duplicates so each kept frame represents one biologically distinct stim.

Where defined

The config block

All three experiments are dictionaries inside EXPERIMENTS in preprint_figures/common/config.py. Add a new experiment by adding another entry. Required fields:

EXPERIMENTS["my_new_exp"] = {
    "dir":            "EXPERIMENTS/.../my_data/",
    "channels":       ["channel 1", "channel 2"],
    "stim_minutes":   [15, 25, 35, ...],          # OR
    "stim_logs":      {"channel 1": "monitoring.log"},  # OR
    "stim_frames":    {"channel 1": [120, 240, ...]},   # manual
    "response_direction": "increase",              # or "decrease"
    "response_window":    (1, 8),                  # frames after stim
    "single_channel_root": False,                  # True for flat layout (PC3-style)
    "filter_dead_frames":  False,
    "time_window_minutes": None,                   # or a float like 30.0
}
Watch out

Per-experiment caveats

Cross-experiment comparisons are NOT directly meaningful

Different cell types, different reporters, different stimuli, different response directions. The pipeline normalizes via dF/F0 to make magnitudes comparable, but biology is not. A "small" response in NRK acid is not the same as a "small" DMSO response in C2C12.

The response direction flag determines whether per_cell_response_delta() uses max or min in the response window. Forgetting it on a "decrease" experiment yields zeros where you expected negatives.

Pooling across channels in C2C12 / NRK is only done when stim timing is aligned (stim_timing_aligned_across_channels). PC3 is single-channel, so pooling is moot.
