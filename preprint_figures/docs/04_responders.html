Responder thresholds

"Did this cell actually respond?" answered statistically. We build a null distribution from pseudo-stimuli during quiet periods and pick a Bonferroni-corrected percentile. Cells whose real |dF/F0| crosses it are responders.

How to study this

  1. Read the null-construction recipe.
  2. Note α = 0.01 and the per-stim Bonferroni division.
  3. Understand the difference between threshold magnitude and direction.
  4. Open common/responders.py in parallel.
Core idea

Build a null, then pick a percentile

The null

Response magnitudes computed at random frames (not at real stims). These reflect what the response window looks like for a non-responding cell — purely from noise + baseline drift.

The threshold

The (1 − α/n_stim) × 100th percentile of |delta| in the null pool. A real response above it is unlikely to be noise after Bonferroni correction.

Per (exp, channel)

Computed independently for each experiment-channel pair, because baseline noise levels differ. Stored as {(exp, ch): threshold}.

Algorithm

Step-by-step

  1. Compute dF/F0. For each cell: F0 = mean of frames [0, first_stim); dF/F0 = (F − F0) / F0. Cells with F0 = 0 get NaN.
  2. Mask the real stims. Exclude frames within ±pad of every real stim, where pad = max(10, response_window_hi). We don't want pseudo-stims to overlap real responses.
  3. Sample 100 pseudo-stims. Pick 100 random frames from the valid (non-stim) region per channel. Each pseudo-stim must leave room for the response window [stim+lo, stim+hi).
  4. Extract pseudo-deltas. For each cell × pseudo-stim: same response-window logic as a real stim. delta = max(window) − baseline for "increase" experiments, delta = min(window) − baseline for "decrease".
  5. Pool the null. Concatenate every (cell × pseudo-stim) delta in this experiment-channel.
  6. Bonferroni-corrected percentile. 
    α       = 0.01
α_per   = α / n_real_stims
pct     = (1 − α_per) × 100        # e.g. 99.93 for 15 stims
threshold = percentile(|null|, pct)
  7. Save. thresholds[(exp, ch)] = threshold.
Defining a responder

Per-cell decision rule

# For each cell, look at every real stimulus.
# Compute the response delta (max or min depending on direction).
# Take the max-magnitude delta across stims:
peak = max(|delta_stim_0|, |delta_stim_1|, ..., |delta_stim_N|)

# A "responder" is a cell where peak ≥ threshold.
is_responder = peak ≥ threshold

Note: it's |delta|, not signed delta. A "decrease" experiment uses the same threshold magnitude — direction is handled by which extremum (min vs max) is taken inside per_cell_response_delta().

Watch out

Sanity checks

What this threshold does and does not say

It's a magnitude test, not a direction test. A cell that responds the "wrong" direction (e.g. luminosity drops in a DMSO experiment) can still be flagged as a responder if the magnitude is large. Direction is enforced upstream by which extremum (min/max) is taken in the response window.

It depends on F0 quality. If the baseline window is contaminated (e.g. early imaging instability), F0 is noisy and dF/F0 is noisy and the null is wider — threshold goes up, "real" responders disappear.

The null assumes 100 pseudo-stims is enough. With heavy tails or strong baseline drift, 100 samples may underestimate the tail. Robustness to this hasn't been audited.

Bonferroni is conservative. 15 stims means we're effectively testing for any-stim significance. Per-stim significance would use a softer correction.

The null is built per (exp, channel), not per cell. So cells with very wide intrinsic baseline noise are held to the population-average threshold and may pass even when their response is dominated by their own noise. Tighter per-cell thresholds would be more cell-specific but harder to estimate from one experiment.
