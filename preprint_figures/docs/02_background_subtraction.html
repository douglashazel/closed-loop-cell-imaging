Background subtraction

Bioluminescence images have spatially-varying background — vignetting, stray light, sensor offset — that drifts over time. The pipeline fits a degree-4 2D polynomial per frame to cell-free pixels and subtracts it before any cell-level analysis.

How to study this

  1. Read the model spec — degree, sample selection, fit method.
  2. Open common/bg_fit.py and trace one frame.
  3. Run the bg_diagnostic figure to see the result.
  4. Note where dead-frame masking sits in the flow.
Core idea

Why bother with a polynomial

Vignetting + drift

Camera optics cause smooth corner-darkening. LED aging and temperature change the global brightness over hours. Both are smooth in (x, y, t), so a low-order polynomial captures them.

Per-frame, not global

The fit is redone every frame. This catches temporal drift. The fit's sample points are static — chosen once per channel and reused across all frames.

Cells must be excluded

Sample points are chosen to be ≥ 40 px away from any mask in 15 reference snapshots. Otherwise the fit absorbs cell signal and overcorrects.

The model

Degree-4 2D polynomial

bg(x, y) = Σ c_ij · (x_norm)^i · (y_norm)^j     for i+j ≤ 4

x_norm, y_norm = (x − cx)/(W/2), (y − cy)/(H/2)    # centered, scaled to [-1, 1]

# 15 polynomial terms total: (4+1)(4+2)/2

# Per frame, sample mean intensity in a circle of radius 30 px around each
# of ~160+ cell-free points, then solve via Moore–Penrose pseudoinverse:
coefs = A_pinv @ patch_means     # least-squares fit

A_pinv is precomputed once per experiment because the sample-point geometry is fixed. Per-frame cost: one matrix-vector product. Fast.

Sample-point selection

Where the polynomial is fit

  1. Cell-free mask. Take 15 evenly-spaced segmentation snapshots across the channel's mask sequence; union them; distance-transform. Pixels with distance ≥ 40 px from any cell across all snapshots are "safe".
  2. Candidate grid. 25 × 25 = 625 evenly-spaced points across the frame, with a 30 px margin from edges.
  3. Snap to nearest safe pixel. For each grid point, find the nearest cell-free pixel within a 180 px search radius. Drop grid points with no safe pixel in range.
  4. Verify count. If fewer than 15 sample points (the polynomial-term count) survive, the experiment errors out. Typical run: 160+ points.
  5. Sample patch. Each sample point gets a 30 px circular patch; mean intensity in the patch is the per-point measurement at every frame.

All controlled by the BG_FIT dict in common/config.py:

BG_FIT = {
    "clearance_r":     40,    # min distance to ANY cell across snapshots (px)
    "sample_r":        30,    # local sample-patch radius (px)
    "grid_n":          25,    # NxN candidate grid
    "search_r":       180,    # max snap distance from grid point
    "n_mask_snapshots":15,    # snapshots used to build cell-free mask
    "poly_degree":      4,    # 2D polynomial degree → 15 terms
    "min_grid_n":     160,    # coarse grid for finding bg surface minimum
}
Per-cell correction

From fit to corrected_lum

for frame f in 0..n_frames:
    coefs = fit_background_from_image(image_f, sampler)         # 15 coefs
    bg_min = min over coarse grid of bg(coarse_x, coarse_y)
    state["bg_coefs_by_ch"][exp][ch].append(coefs)
    state["bg_min_by_ch"][exp][ch].append(bg_min)

for cell c at frame f:
    x, y = trajectory[c][f]
    bg_at_cell = polynomial(x, y, coefs)
    corrected_lum[c][f] = raw_lum[c][f] − bg_at_cell           # baseline-aligned

If (x, y) is missing or out of bounds the cell is skipped at that frame. raw_lum comes from analysis/luminosity_complete.json which already contains per-cell mean intensity (the upstream tracking + Cellpose stage).

Diagnostic data

What the bg_diagnostic figure consumes

The pipeline stores enough to render the QC figure:

  • Probe frame — the middle frame of the recording, kept raw + corrected.
  • Probe sample mean — mean intensity at the cell-free sample points on the probe frame.
  • Bg trace — for every frame, the mean of all sample-point intensities. Saved as a (n_frames,) array. This is the time-series shown in the diagnostic's right column.
  • Bg map — the 2D fitted background surface evaluated on a fine grid at the probe frame. Lets you see what's being subtracted.
  • Bg min/max — over a coarse 160 × 160 grid, used for color-scale alignment between the raw and corrected probe panels.
Dead-frame masking

Catching dropouts and flashes — two stages

Optional, opt-in via filter_dead_frames: True per experiment. PC3 turns it on; C2C12 and NRK leave it off. Both stages share detect_dead_frame_indices() in common/pipeline.py so the index sets always agree.

Stage 1 — fix the BG fit

Inside compute_background_correction(), after the per-frame polynomial fit pass:

  1. Detect dead-frame indices on the sampled bg_trace (rolling-median, window = 21 frames; |residual| > 6 σ where σ = 1.4826 × MAD).
  2. For each dead frame, linearly interpolate every polynomial coefficient and the bg_min value across the surrounding non-dead frames (_interpolate_bg_at_dead_frames).
  3. Per-cell correction loop now uses the interpolated coefs at dead frames, so anomalous frame fits don't leak into corrected_lum or the cached BG maps.

Stage 2 — mask + fill the per-cell trace

After prepare_state clipping, mask_dead_frames() and fill_dead_frames() still run:

  1. mask_dead_frames sets corrected_lum[exp][ch][cell][f"f{idx}"] entries on dead frames to NaN — the cell's raw luminosity at those frames is still bad.
  2. fill_dead_frames linearly interpolates the per-cell trace across NaN entries, so downstream code sees smooth traces with no NaN handling.
Cache invalidation

Why the cache filename has a suffix

__filterdead in the pickle path

When cfg["filter_dead_frames"] is True, the BG cache lives at bg_cache/<exp>__filterdead.pkl; otherwise at bg_cache/<exp>.pkl. Toggling the flag therefore changes the path — a stale cache from the other setting cannot be silently reused. The pickle also carries a PIPELINE_VERSION field (currently 2); bumping it forces a recompute on next run, which is how you invalidate every cache after changing pipeline semantics that aren't expressed in BG_FIT.

Watch out

Sanity checks

This step is a common source of artifacts

Sample points on cells. If a cell drifts into a sample point, that point's measured "background" includes cell signal. The fit gets pulled high → cells get over-subtracted → spurious negative dF/F0. Check the bg_diagnostic figure column 1 (sample-point overlay) and column 3 (corrected image): cells should appear as dim/dark patches, not as enhanced features.

Polynomial can't capture sharp features. Dust spots, sensor hot pixels, optical aberrations are not smooth and will leak into the corrected image as residuals. If your "corrected" image has visible halos or stripes, that's why.

The fit is sensitive to outlier sample points. The pseudoinverse is a least-squares solution; one wildly anomalous point can tilt the surface. There's no robust regression here.

Cache + config drift. The cache invalidates on BG_FIT changes and on PIPELINE_VERSION mismatches; toggling filter_dead_frames changes the cache path, so the two settings keep separate pickles. Other config edits (e.g. time_window_minutes, response_window) don't trigger a rebuild — force --recompute-bg after those.
