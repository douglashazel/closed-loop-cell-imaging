Pipeline overview

How raw image folders become a single in-memory state dict that every analysis script reads from. Knowing this map saves you from chasing ghosts in the analysis pages.

How to study this

  1. Memorize the six pipeline phases.
  2. Skim the state-dict shape — every key matters later.
  3. Note where the cache lives and what invalidates it.
  4. Run run_figures.sh with one experiment to see it work.
Core idea

One state, eight scripts

Why a shared state

Background correction is the slow part — minutes per experiment. Doing it once and caching makes subsequent analyses cheap. prepare_state() in preprint_figures/common/pipeline.py is the single entry point.

What you get

Every analysis script calls prepare_state(experiments) at the top, then indexes into it. No script ever opens raw frames or segmentations directly.

Frame ↔ time

Frames carry no time info on their own. The mapping is built late — during visualization — via frames_to_min(), so the data layer stays time-agnostic.

Data flow

From raw frames to state

Six phases run in order inside prepare_state(). Each produces a layer of the state dict.

  1. Stim resolution — resolve_all_stim_frames() turns minutes (or log entries) into frame indices per channel. Mutates cfg["stim_frames"] in place. Details →
  2. Background correction — compute_background_correction() fits a degree-4 polynomial to cell-free pixels per frame. When filter_dead_frames=True, dead-frame indices are detected on the sampled bg_trace via detect_dead_frame_indices() and the per-frame polynomial coefs (and bg_min) at those indices are linearly interpolated from the nearest non-dead frames (_interpolate_bg_at_dead_frames()) before the per-cell correction loop runs, so the per-cell pass sees a clean BG estimate. Cache hit short-circuits this. Details →
  3. Time axis — build_frame_to_minutes_lookups() builds (known_frames, known_minutes) arrays per channel by parsing monitoring.log / timestamps.csv / file mtimes. Also extracts NRK real setpoint time.
  4. Time-window clip — if cfg["time_window_minutes"] is set (NRK = 30 min), trim corrected_lum, bg_trace, stim_frames to that window.
  5. Dead-frame mask — opt-in (filter_dead_frames: True, used by PC3). Rolling MAD on the bg trace; outliers above 6 σ get NaN'd in corrected_lum. Same detect_dead_frame_indices() as phase 2 — both passes agree on the index set.
  6. Dead-frame fill — linear interpolation between valid neighbors so downstream code doesn't need to handle NaNs.
  7. Direction sanity check — confirm_response_direction() in 04 · Responders pools (max−base) and (min−base) magnitudes across every cell × stim per (exp, ch) and prints an [OK] / [WARN] line. Diagnostic only — cfg["response_direction"] still drives the rest of the pipeline.
State dict shape

What the analyses index into

state = {
    "corrected_lum":  {exp: {ch: {cell_id: {"f0": v0, "f1": v1, ...}}}},
    "bg_trace":       {exp: {ch: np.ndarray (n_frames,)}},        # mean of cell-free sample points per frame
    "frame_counts":   {exp: {ch: int}},
    "traj_by_channel":{exp: {ch: {cell_id: {"x0": x, "y0": y, ...}}}},
    "frame_minutes_src": {exp: {ch: (known_frames, known_minutes)}},  # for frames_to_min()
    "real_setpoint_min": {exp: {ch: float | None}},               # NRK only
    "probe_data":     {exp: {ch: {probe, corrected, probe_idx, probe_sample_mean, ...}}},  # bg_diagnostic
    "bg_map_by_ch":   {exp: {ch: 2D fitted bg surface at probe frame}},
    "bg_coefs_by_ch": {exp: {ch: list of poly coefs per frame}},
    "bg_min_by_ch":   {exp: {ch: per-frame surface minimum}},
    "bg_sampler_by_exp": {exp: sampler dict (re-evaluatable at arbitrary points)},
    "bg_sample_points_exp": {exp: list of (x, y) cell-free points},
    "direction_check": {(exp, ch): {"configured", "empirical", "agreement",
                                    "abs_increase", "abs_decrease"}},
}

Frame-number keys in corrected_lum are strings like "f0", "f1"; trajectory keys come in x0/y0/x1/y1/... pairs. Many helpers convert these to dataframes via lum_dict_to_df().

Caching

The bg cache

Where it lives

April28_preprint_results/bg_cache/<exp_name>.pkl for experiments without dead-frame filtering, and <exp_name>__filterdead.pkl when cfg["filter_dead_frames"]=True (PC3). Suffixed paths mean toggling the flag never silently reuses a stale cache. ~100 MB each.

What invalidates it

The pickle carries a PIPELINE_VERSION field; mismatched versions trigger a recompute. A different cached BG_FIT config also rebuilds automatically. Add --recompute-bg on the CLI to force a rebuild. Re-running the same analysis script after the first build is essentially instant.

Cluster cache

Cluster labels persist alongside the bg cache at bg_cache/clusters/<exp>__<ch_or___pooled__>.pkl (written by common/cluster_labels.py). Read by four downstream scripts — dff, correlation_distance, response_violins, learning_scores — for stratified per-cluster figures. Missing cache → those figures are silently skipped.

Script ordering

Why clustering runs first

Order in run_figures.sh

clustering runs before dff, correlation_distance, response_violins, and learning_scores so that those scripts can read the per-channel cluster labels and emit per-cluster panels. Without the cache they fall back gracefully — but you lose the stratified figures.

Sliding correlation

sliding_correlation is now part of the default ALL_ANALYSES list. It is still the slowest analysis; remove it from ANALYSES in run_figures.sh to skip.

Watch out

Sanity checks

Don't trust the cache blindly

If you change the config (e.g. filter_dead_frames, time_window_minutes, response_window) the cache will not auto-invalidate — only changes to BG_FIT trigger that. After non-bg config edits, force --recompute-bg or delete the pickle.

Frame indices in state["corrected_lum"] are sparse — cells that weren't tracked at frame N just don't have an "fN" key. Code that expects a contiguous range will silently miss frames. Helpers like lum_dict_to_df() handle this; ad-hoc loops may not.

NaN appears in two places: (1) cells with missing tracking, and (2) frames killed by the dead-frame mask. Many analyses use nanmean / nanstd; a few use plain mean. Check the script.
