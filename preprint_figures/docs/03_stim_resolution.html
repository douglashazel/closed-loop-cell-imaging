Foundations · 03 · Stim timing

Stim frame resolution

Three sources of truth for "when did the stim hit", with a strict precedence chain. Knowing which one your experiment uses explains why C2C12 has clean stim shading but NRK has many small pulses.

How to study this

  1. Read the precedence chain — only one source wins per channel.
  2. Trace a real example for one experiment.
  3. Note the dedup rule for NRK acid pulses.
  4. Open common/stim_resolve.py in parallel.
Core idea

One output, four possible sources

The output

cfg["stim_frames"][ch] = list[int] — frame indices (0-based) where the stim hit. Mutated in place by resolve_all_stim_frames().

The strict order

1. stim_logs[ch] (NRK) → 2. stim_minutes + timestamps[ch] (C2C12, PC3) → 3. stim_minutes + file mtimes (PC3 fallback) → 4. manual stim_frames[ch]. The first available source wins.

Why per-channel

NRK runs each channel independently against its own monitoring log. Even when channels share a wall-clock, the pipeline never assumes alignment.

Source 1 · Hardware log

NRK: parsing monitoring.log

Used by nrk_acid_13APR26. Each acidic-media injection by the feedback controller writes a line.

15234_channel1 : ... -> add acidic media     # frame 15234, channel 1
15301_channel1 : ... -> add acidic media     # frame 15301, channel 1 (same train)
...
  1. Regex extracts (frame_idx, channel_num) from every line containing add acidic media.
  2. Filter to the channel of interest.
  3. Deduplicate. Drop any frame within PULSE_DEDUP_FRAMES = 10 of the previous kept frame. The controller fires multiple pulses per "decision" event; we want one event per biological stimulus.
  4. Output: a sorted list of frame indices.

The log also records setpoint changes; the second one is treated as the "real setpoint" and stored separately in state["real_setpoint_min"]. The first is the initial stabilization period.

Source 2 · Per-channel CSV

C2C12 and PC3: stim minutes + timestamps CSV

Used by both c2c12_dmso_09APR26 and pc3_dmso_23MAR26. Each carries stim_minutes (e.g. [15, 25, 35, ...] for C2C12; [10, 20, 30, ...] for PC3) and a timestamps entry pointing to a per-channel CSV.

  1. For each channel, load the timestamps CSV with columns filename, datetime, minutes. PC3 keeps its CSV at <dir>/PC3 DMSO pulses perfusion 23MAR26 timestamps.csv (single-channel root); C2C12 uses one CSV per channel under timestamps/.
  2. The acquisition's perfusion start is the earliest datetime across all channels (or an explicit perfusion_start if given).
  3. For each m in stim_minutes: target wall-clock = perfusion_start + m minutes.
  4. Pick the frame whose datetime is nearest to the target.
  5. Output: [frame_idx_for_each_stim_minute].

Confirmed: PC3 uses the CSV path, not file mtimes — same as C2C12. The mtime fallback below is only invoked when a single-channel-root experiment lacks a CSV; PC3 has a CSV, so source 3 never fires for it.

Source 3 · File mtimes (unused in current configs)

Fallback for single-channel root without a CSV

Available for any single-channel-root experiment that lacks a timestamps CSV. None of the current configs trigger it (PC3 has a CSV).

  1. Take frame mtimes in order.
  2. deltas = diff(mtimes), clamped to non-negative.
  3. minutes = cumsum(deltas) / 60.
  4. For each m in stim_minutes, find the nearest-minute frame.
Source 4 · Manual

Last resort: explicit frame list

If stim_frames is set in the config (either as a list — broadcast to all channels — or a per-channel dict), it's used as-is. Lowest precedence: only used when nothing higher is available. Useful for ad-hoc experiments without timestamps.

After resolution

What the rest of the pipeline does with stim_frames

  • F0 baseline (in stim_helpers.py) — per-cell mean of frames [0, first_stim). So if stim_frames[0] = 850, F0 averages frames 0–849 for every cell.
  • Response window — for each stim frame p, examine frames [p + lo, p + hi) where (lo, hi) = cfg["response_window"]. Compute max (or min for "decrease" experiments) minus baseline.
  • Stim spans on plots — convert frames to minutes via frames_to_min(), build (start_min, end_min) for each stim, fill via draw_stim_spans() with red shading at α=0.18.
  • Time-window clip — when time_window_minutes is set, stims past the window are dropped.
Worked examples

What the printout looks like

c2c12_dmso_09APR26 / channel 1    → 15 stims  [903, 1505, 2107]...[12076, 12679, 13282]
c2c12_dmso_09APR26 / channel 2    → 15 stims  [905, 1507, 2110]...[12080, 12683, 13286]
pc3_dmso_23MAR26   / channel 1    → 15 stims  [612, 1224, 1836]...[10404, 11016, 11628]
nrk_acid_13APR26   / channel 1 A  → 42 stims  [274, 485, 896]...[3847, 3952, 4061]   (after dedup)

C2C12 and PC3 hit a clean 15 stims because they're on a fixed protocol. NRK's stim count varies with how many feedback decisions the controller made.

Watch out

Sanity checks

If stim shading looks wrong, this is where to look

Wall-clock vs frame timing. Source 2 (timestamps.csv) trusts the camera-recorded datetime. If that's wrong (e.g. system clock drift between channels), the resolved frame index will be off by however many frames ≈ that drift. The resulting stim shading will sit a few frames before/after the real event.

Dedup window. PULSE_DEDUP_FRAMES = 10 works for ~1 Hz acquisition. If frame rate changes, the threshold may merge distinct stims (too coarse) or fragment one stim into many (too fine).

Channel alignment for pooling. Several analyses (dff mean-pooled-responders, response_violins pooled, learning_scores) require stim_timing_aligned_across_channels. C2C12 channels usually align; NRK channels often don't (each runs its own feedback). When alignment fails, those pooled figures are silently skipped.

Manual override. If you set stim_frames manually for debugging, remove the higher-precedence sources or they'll win. The order is strict.
